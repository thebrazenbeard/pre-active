## Research reality check

The V1 scope remains justified.

- Linear Hawkes processes model self-exciting event arrivals. Exponential kernels admit a finite-dimensional Markov representation; this supports durable recursive state without replaying the complete event history.
- For the V1 kernel `alpha * exp(-beta t)`, the branching ratio is `alpha / beta`; rejecting `alpha / beta >= 1` is a conservative subcriticality bound.
- ARIMA/SARIMA/SARIMAX consume an observed time-series process (`endog`) with lag/order/frequency semantics. The current observer contract is a snapshot/evidence contract, not a regular numeric-series contract, so adding those models to generic observers in V1 would be premature.
- The current Hawkes implementation is a deterministic initiative score over *detected changes*. It is not a claim that the file changes themselves were generated by a Hawkes process and it is not a calibrated probability of importance.

Research references:

- Laub, Lee, Pollett, Taimre, *Hawkes Models And Their Applications* (2024): https://arxiv.org/abs/2405.10527
- Browning et al., *Parameter Estimation of Binned Hawkes Processes* (branching ratio for exponential kernel): https://www.tandfonline.com/doi/full/10.1080/10618600.2022.2050247
- statsmodels `ARIMA` documentation: https://www.statsmodels.org/stable/generated/statsmodels.tsa.arima.model.ARIMA.html

## Hostile challenges

> **HOSTILE REVIEWER:** A Hawkes layer may be unnecessary complexity if ordinary on-change emission already works.

**PARTIALLY ACCEPTED.** The default remains `on_change`; Hawkes is opt-in. The extra state is justified only for observers where clustered changes should accumulate initiative before granting a turn. No other statistical family was added merely to populate a model catalog.

> **HOSTILE REVIEWER:** The implementation calls a post-event value an intensity even though classical conditional intensity is predictable from events strictly before the event time.

**ACCEPTED AND BOUNDED.** V1 explicitly uses `post_intensity`: the detected change first increments exponential excitation, then the resulting post-event activity level is compared with a wake threshold. This is an initiative score derived from Hawkes recursion, not a claim that it is the pre-event likelihood of the observed change.

> **HOSTILE REVIEWER:** File observers do not know the true occurrence time of a content change; polling time can distort clustering.

**ACCEPTED.** Documentation bounds the model to observation/detection time. V1 does not infer latent event time from file metadata. This means polling cadence is part of the effective temporal resolution.

> **HOSTILE REVIEWER:** One corrupt initiative record could escape the per-observer failure boundary and stop other due observers.

**ACCEPTED; FIXED.** The first hostile test corrupted persisted `state_json` and demonstrated that `_claim_due()` decoded initiative state before the guarded decision path. Red commit: `6c1b196182461b1fbe632b1c67718da2209df087`. Fix: `47a317827270165f2117972a04900d40181d10cf` makes claim materialization observer-core-only; initiative JSON is decoded inside `_record_observation()`, where failure is isolated and journal/error handling continues with later observers.
